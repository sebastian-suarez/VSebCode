# UI step 3, full-height column and band heights: review findings not acted on

The implementation of the column and band step (`docs/plans/ui-step-3-column-and-bands.md`) had two review rounds on 2026-10-20, each with an adversarial review of the change with the plan and a fresh-context review of the change alone. The reviewer the protocol names for the fresh-context slot was out of quota for both rounds, so its stand-in took the slot; the stand-in's first round 2 run broke off with an interrupted stream and was run again. The findings that were acted on are listed in the plan's Review section: in round 1, the maximized secondary side bar while the side bar moves, top-right notifications without the title row, the debug toolbar's range after a zoom change and its default place in an auxiliary window, the splash widths under a maximized secondary side bar, and the title row's inset after leaving full screen; in round 2, the debug toolbar's range after an auxiliary window leaves full screen, the notifications' anchors against the bands as laid out, the splash widths in a window narrower than the saved layout, and, as hardening, the title row's inset set before the title bar lays out and kept across relayouts that pass no position. The findings below were checked against the code, the captures or a test and rejected, with the evidence.

| Finding | Source | Decision and evidence |
|---|---|---|
| `adjustPartPositions` replaced the guard `this.isVisible(Parts.PANEL_PART)` with `isPanelVertical`, so it resizes a hidden vertical panel with `Sizing.Invisible` objects (NaN sizes), and a visible horizontal panel moved into the main area loses its height. | Fresh-context review, round 1, finding 1; again in round 2, finding 1 (the first part) | Rejected. Upstream has the same block, `if (isPanelVertical)` with the same `as number` casts (`git show upstream-base:src/vs/workbench/browser/layout.ts`, lines 2035 to 2041), so no guard was replaced. `GridView.resizeView` applies only sizes whose `typeof` is `number` (`gridview.ts`, lines 1454 and 1461), so an invisible sizing is ignored rather than turned into NaN. `Grid.moveViewTo` re-adds a view moved across branches with its size along the source branch's orientation (`grid.ts`, `moveViewTo`), so a panel moving from the editor's column into the main area keeps its height: the captures measure the bottom panel at 292px both centered and justified. |
| The debug toolbar's range takes the main window's title row visibility for an auxiliary window, because `Layout.isVisible(Parts.TITLEBAR_PART, window)` answers for the main window, so its lower limit can exceed the upper one. | Fresh-context review, round 1, finding 3 (part); round 2, finding 3 | Partly acted on in round 1: the default place and the upper limit read the active window's container offset, which counts that window's own title row (none while hidden) and the main window's banner. The lower limit keeps upstream's rule, 0 while the title row shows, otherwise the main window's offset: it only decides whether the toolbar may be dragged over the title row, the inverted range needs both windows in full screen with their title rows hidden, a banner and no editor tabs, and it then resolves to the banner's height, as it does upstream. Changing what `isVisible` answers for auxiliary windows would reach every other caller. |
| The debug toolbar's cached range is not cleared when Modern UI, its density or the activity bar location change. | Fresh-context review, round 1, finding 3 (part) | Partly acted on: the zoom case is fixed (the pixel-ratio listener clears the range). Modern UI and its density already cleared it (the configuration listener of `debugToolBar.ts`), and the activity bar location does not change the title row's height. |
| `MainNativeTitlebarPart.layout` sets the title row's inset after `super.layout` has measured `.titlebar-container`, so a layout that changes the left column measures with the previous inset. | Fresh-context review, round 2, finding 2 (the first part) | Rejected as stated: `BrowserTitlebarPart.updateLayout` measures nothing (it sets the zoom factor, lays the custom menu bar out and toggles a class), and the toolbar overflow check runs from a scheduler after the layout returns. The variable is now set before `super.layout` anyway, together with the hardening of the second part. |
| Top-right notifications add upstream's 35px (`DEFAULT_CUSTOM_TITLEBAR_HEIGHT`) to their inline `top`, which overlaps the 44px title row. | Fresh-context review, round 2, finding 4 | Rejected. Wherever the 44px title row exists Modern UI is on, and Modern UI's `modern-ui-notifications-dialogs` class (toggled with Modern UI in `modernUI.contribution.ts`) applies an `!important` `top` from `--modern-ui-notifications-block-start-inset`, which the toasts and the center now set from the title row's height: the captures measure the center at 45px under the 44px title row and 1px below the 52.8px title row at 83% zoom. With Modern UI off the title row keeps upstream's heights, for which upstream's inline offset is made. |
