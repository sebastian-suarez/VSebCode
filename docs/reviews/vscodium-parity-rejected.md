# VSCodium parity review decisions

The first review round used immutable snapshots of every changed hunk and every new file, grouped into build, runtime, font controls and font views, with additional complete supporting files. The task-aware review completed for all four groups. The artifact-only review completed for build and both font groups; its runtime invocation timed out after 1,800 seconds and provides no approval. Subsequent verification and the final review are recorded in the validation report.

## Findings not adopted

| Finding | Evidence and decision |
| --- | --- |
| ADMX branding no longer matches the native Windows watcher. | Rejected as factually incorrect for the installed package. `@vscode/policy-watcher/index.d.ts` exposes `WatcherOptions.registryPath`, and `src/vs/platform/policy/node/nativePolicyService.ts` supplies `Software\\Policies\\SebastianSuarez\\${productName}` through that argument. The generated template uses the same approved vendor segment. Windows execution remains deferred. |
| Missing or unsupported affected source maps should be ignored so installation succeeds. | Rejected because it contradicts the accepted source-map requirement in `docs/plans/vscodium-parity-acceptance.md`: preserve mappings and fail with a path-specific diagnostic when fidelity cannot be maintained. Normal installation, the cache path and packaged built-ins pass with the current dependencies. A future malformed affected dependency can deliberately block preparation until repaired. |
| Restore fatal dependency-reference mismatch checks on existing Linux architectures. | Not adopted: the pinned `linux/31-build-fix-dependencies.patch` explicitly changes the flag to warning-only. The generated dependency list, not the old reference, is returned to packaging, so the claim that this necessarily ships the old incorrect dependencies is unsupported. Linux package execution and new reference lists remain deferred. |
| Remove directory and plain-text desktop associations. | Not adopted: both associations appear in the pinned VSCodium `src/stable/resources/linux/code.desktop` and `src/insider/resources/linux/code.desktop`. Registering handlers is part of the requested conveniences; this change does not write the user's default-handler configuration. Desktop-dependent selection behavior is not validated on macOS. |
| Skip the telemetry scan when fast installation reports an unchanged state. | Not adopted: the accepted requirement explicitly includes cache/skip paths and late downloads. A lockfile stamp alone would miss new cached or installed text. The preparation fixture demonstrates rewriting a late built-in cache entry and hidden dependency files through the up-to-date fast-install entry point. The synchronous scan has a cost and remains idempotent. |
| Restore the RPM release revision and remove `%config(noreplace)` from product.json. | Not adopted: both are explicit effects of the pinned `linux/00-asset-fix-rpm-version.patch` and the accepted packaging scope. Consequences remain visible: same-version RPM respins do not gain a newer release number, and an edited packaged product.json can retain older metadata on upgrade. No Linux package publication or upgrade validation is claimed. Per-user product overrides are also available. |
| Restore the removed Command Palette AI/NLP settings because they are unrelated to fonts. | Rejected as a scope inference from the artifact-only grouping. Removing compatible telemetry/AI leftovers is part of the full task. A source search found no remaining consumers of the three removed configuration keys, and the client/API checks cover the surviving code. Local Settings search and command suggestions remain. |

## Confirmed findings

Accepted fixes cover custom sysroot path validation, external-source and URI-encoded source maps, the RPM LoongArch name, pending command authorization, non-Linux log paths, terminal shell failures, fixed-tab sizing, live Find geometry, font invalidation and row preservation, container-aware view metrics, notification and pane-header scaling, narrow Extensions search, SCM input padding, explorer alignment, CSS selector scope and cached font measurements. The RPM architecture correction follows the canonical `loongarch64` entry in [RPM's architecture table](https://github.com/rpm-software-management/rpm/blob/master/rpmrc.in); Debian retains `loong64`.

Repeated findings across the two review streams are tracked as the same defect. Additional failures found by the package acceptance checks are fixed and rerun before the final review. No failed invocation is treated as approval.

## Final-round decisions

The final-round font-control findings about stale horizontal widths, hidden dynamic-row measurements, detached list metrics and fractional Find reset dimensions were accepted. Focused tests cover retaining live rows, deferred measurement after reveal, initial attachment and reattachment into a region with a different font size. Find uses the same rounded minimum width for rendering, dragging and reset comparisons; the packaged regression supplement exercises a 14px UI font.

The claimed pane-header double scaling was rejected after inspecting all production callers: `ModernUIContribution.applyPaneHeaderSize` passes unscaled 22 or 28, and disposal passes 22. The exported helper now explicitly documents its base-13 units. A connected-region test confirms that a rendered pane attached beneath a 26px font receives a 56px logical header for the 28px base, with no second multiplication.

The claimed cached pre-attachment pane-header style was not reproduced: `Pane.updateHeader` does not write height or line-height, `SplitView.doAddView` attaches the pane before relayout, and the pane's size getter reads the current container. Workbench CSS supplies regional header geometry. `FindInput.layout` already recomputes toggle padding after attachment. Paged lists pass their delegate directly, tree adapters forward the container, and the table adapter uses a separate, unchanged table-delegate contract with fixed row sizes. These paths do not substantiate the suggested missing propagation in the supplied changes.

The final artifact-only workbench review inferred that tree delegates never receive their host element. This was rejected against the fork's implementation: `ListView` supplies `this.domNode` during splice and remeasurement, and `ComposedTreeDelegate` forwards it to the underlying delegate. The moved-view package checks exercise regional sizing. The suggested scaling of explicit fixed-tab widths was also rejected: these settings are pixel widths, and the accepted regression requires preserving the user's 240px setting and the existing hover width freeze. The CSS fallback applies only when the corresponding explicit control variable is absent.

The synchronous font-listener ordering concern was rejected after inspecting the publishers: sidebar, auxiliary-bar, panel and workbench code write their CSS font variable before invalidating metrics. Initial detached control measurements were a separate confirmed defect; search-input options, trailing tree padding, open-editor constraints and call-stack frame metrics now refresh on layout. Call-stack ordinary/skipped rows use one container-derived metric, including their CSS header and test-output scroll offset. A real editor/list fixture checks initial attachment and subsequent regional changes.

The source-only inline-map finding was reproduced with omitted and null source content, then fixed for file-map transforms and directory discovery. The Windows UNC finding was confirmed from startup ordering; the selected host is authorized before loading its product overrides in desktop and CLI startup. Native Windows execution remains deferred. The initial Linux per-profile isolation fix was extended after the maintainer chose path precedence: explicit CLI/app-data roots keep their own logs unless app-state overrides them. That override retains separate profile subdirectories; default and portable layouts remain.

The final extension review correctly identified that unconditional copy/move guards also rejected a metadata-only operation at an unchanged existing location. That case now remains available; introducing an ID to a destination profile or replacing its location remains blocked. The review's recommendation to allow updates and reinstalls was not adopted: the maintainer explicitly chose to block installs and updates, including reinstalls, while leaving existing copies running. Tests cover the unchanged-location operation and both prohibited destination cases.

The fallback reviews reproduced URI-encoded inline maps containing literal asterisks and a command registered while its confirmation is pending. The parser now distinguishes line-comment source-map URLs from block-comment terminators, and command registration is checked after confirmation. Both fixes have regression coverage. The suggested per-row font cache was not adopted: remeasurement reads all row sizes before rendering, so it does not interleave per-row DOM writes with style reads. A local 50,000-row attached-list check measured approximately 27ms for initial insertion and 24ms for font remeasurement; this is one-machine evidence, not a performance guarantee. Caching would also require invalidation when views move between regions.

The retried artifact-only view-CSS review repeated the detached-measurement concern from its unchanged second-round snapshot. That concern is addressed by the attachment/layout corrections above, with retained-list, real search editor/call-stack and moved-view package checks. The helper intentionally falls back for an unconnected element; its documentation no longer promises a region can be inferred before attachment.

The same review inferred that raw font variables may be absent during startup or in auxiliary windows. This was rejected against `Workbench.renderWorkbench`, which publishes the global size before creating parts, `applyFontStylesToNewContainers`, which copies it to new containers, and `updateFontSize`, which updates every container. Regional parts publish their own variables. The packaged auxiliary-window and restart checks confirm this contract. The generic 13px fallback still serves controls used outside the complete workbench, including test fixtures. `StatusBarActionViewItem.render` places the SCM action class on the parent action-item as the CSS expects. The fixed numbers in the debug toolbar's `yRange` describe its allowed title/tab anchor range, not the toolbar element's height; its CSS height scales separately.

The retried build review again suggested silently accepting unavailable source maps. That conflicts with the accepted source-map preservation contract and remains rejected. Its separate string-literal false-positive and whitespace-before-block-terminator cases were reproduced and fixed: real syntax comment ranges now distinguish directives from strings, templates, regular expressions and nested examples. Regression tests include same-line and block-comment inline maps, and retain the error for an affected map followed by executable code. Its HTTP-download finding was also confirmed; Chromium archives now use the existing retrying, redirect-aware, checksum-verifying download helper. A real local HTTP server exercises a 503 response, redirect, truncated response, successful extraction/cache reuse and persistent 404 failure without stubbing globals.

The retried runtime-features review inferred that extension target mappings live beside `TargetPlatform` in `extensions.ts`. In this version they live in `platform/extensionManagement/common/extensionManagement.ts`; all four added targets have string, host and display-name mappings there, including Node's `ppc64` alias. A parent-run check of the compiled functions confirms all five architecture spellings. Its command-registration finding duplicates the already-fixed confirmation race and its regression test.

The policy binding question was checked beyond declarations: installed `@vscode/policy-watcher` 1.6.0 includes `src/main.cc`, which reads the fourth argument's `registryPath`, `PolicyWatcher.hh` and the Windows policy constructors, which carry it through, and `src/windows/RegistryPolicy.hh`, which uses the custom path directly instead of the Microsoft fallback. `nativePolicyService.ts` and `build/lib/policies/basePolicy.ts` both use `Software\\Policies\\SebastianSuarez\\<productName>`. This is source-level confirmation; Windows execution remains deferred.

The retried product review identified a real separately bundled CLI path problem, although its main-process example did not reproduce: main startup shares its bootstrap pin, but the CLI bundle contained a different module-local pin. A packaged CLI with a user product name override created a second data directory. The pin is now process-scoped across bundle copies; a two-bundle regression and the version 5 packaged fixture check the selected directory.

The proposed change from recursive product merging to atomic gallery replacement was rejected against the approved merge contract and the pinned `00-settings-user-product.patch`: its lines 85–104 recursively merge objects and replace arrays, rather than using the top-level assignment described by the review. The fork's null/scalar replacement and prototype-key filtering are explicitly accepted behavior. The default gallery is Microsoft Marketplace, not the Open VSX default inferred by that review. Users can replace every desired provider field; silently changing merge semantics would contradict the task.

The runtime-extension review's publication-time concern was confirmed in `toExtension`: overall lastUpdated can describe a newer prerelease rather than the offered stable version. The maintainer approved carrying the selected version's timestamp separately and using it for the cooldown. Existing zero, rounding, future-date and invalid-date behavior remains. The batch-profile concern was also confirmed: prohibited IDs are now skipped with a log entry while permitted extensions continue, and already-installed blocked IDs are not offered prohibited updates. Deprecation migration checks the replacement ID before requesting it, and checks the compatible result before fetching its manifest.

Missing-context questions were checked against the complete implementation and existing acceptance evidence: native window configuration carries userStateDir; IPC runtime-directory changes and native dependency replacements are present; the worker bootstrap's CSP digest is tested and the packaged worker activates. Server and standalone-web products remain deleted by maintainer decision. These checks do not imply that unprovided files were covered by an individual artifact-only snapshot.
