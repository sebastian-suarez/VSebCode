# Phase 4: Chat core, agents window, agent host and the chat extension API

Executable plan for the fourth removal phase of the VSebCode fork. It is written for a fresh Claude Code session: read `CLAUDE.md` first, then this file, then work top to bottom. Every path was taken from the removal map of `CLAUDE.md` and from the leftovers phase 3 recorded in its Status section at the end of phase 3 (2026-10-14); re-check with `git ls-files <path>` or `git grep` before acting, because upstream merges move things. Counts are non-test `.ts` files unless stated otherwise and date from the removal map.

## Confirm first (ask)

- The two scope corrections listed under "Open decisions" in `CLAUDE.md`: the agent host (`src/vs/platform/agentHost`, `src/vs/workbench/services/agentHost`, 310 chat importers) and the agents window (`src/vs/sessions` plus its awareness layer, about 190 files outside the folder) leave in this phase together with the chat core. Phase 3 already kept null implementations of the Microsoft services they inject on that assumption.
- Where "AI" stops at the editor level: `src/vs/editor/contrib/inlineCompletions` and the `InlineCompletionItemProvider` API are generic ghost-text infrastructure (also used by non-AI providers) and this plan keeps them; `src/vs/workbench/contrib/browserView` (the integrated browser) is used by agents but is also a user feature, so **ask** whether it stays. `contrib/speech`, `contrib/agentsVoice` and `terminalContrib/voice` are the voice input for chat and leave; **ask** whether the generic `ISpeechService` extension point (`vscode.proposed.speech.d.ts`) should stay for third-party dictation extensions.
- The `agent` CLI subcommand (`NATIVE_CLI_COMMANDS` in `src/vs/platform/environment/node/argv.ts`, rejected since phase 3 because the Rust CLI is gone) and the `--agents` window flag leave with the agent host; confirm that no other launcher depends on them (`resources/*/bin`, `scripts/code-sessions-web.*`).
- Order inside the phase: dependents first, the chat core last, the extension API after the core, the null services and the long tail at the end. Each section below is a commit boundary; keep the mechanical deletion separate from the adaptation commit.

## Ground rules

- One surface per commit, mechanical deletions separate from edits to surviving code (see "How to work in this fork" in `CLAUDE.md`).
- Items marked **ask** are maintainer decisions. Ask before acting on them; do not assume.
- Validation after each section that touched the named inputs:
  - anything under `src/`: `npm run typecheck-client`, then `npm run valid-layers-check` (folders were deleted), `npm run eslint -- <changed .ts files>`, and the unit tests next to the adapted code (`./scripts/test.sh --run <file>` or `npm run test-node -- --run <file>`). Remove the `eslint.config.js` import-pattern entries, the `src/tsec.exemptions.json` entries, the `build/lib/i18n.resources.json` entries and the `.eslint-allowed-bracket-notation-files` entries that name deleted folders.
  - `src/vscode-dts/**`: `npm run gulp compile-api-proposal-names` (regenerates `src/vs/platform/extensions/common/extensionsApiProposals.ts`, never edit it by hand), then `npm run vscode-dts-compile-check`, and remove every `enabledApiProposals` entry and `tsconfig.json` reference of the deleted proposals under `extensions/*`.
  - `build/**`, `scripts/**` or `eslint.config.js`: `cd build && npm run typecheck && npm run test` (one pre-existing failure in `build/next/test/resources.test.ts` on macOS: a `/private/var` versus `/var` temp-path mismatch; anything else is new), then `npm run eslint -- <changed files>`.
  - `package.json`, `remote/package.json`, `remote/web/package.json`, `extensions/*/package.json` or `build/npm/dirs.ts`: `npm install` after the manifests changed (it refreshes the lock files; never edit them by hand) and `npm run install-fast -- --force` once at the end of the phase; the tree must stay clean afterwards.
  - Any file with a copyright header: `npm run precommit -- <files>`.
  - End of phase: `npm run compile-client`, `./scripts/code.sh --user-data-dir .build/smoke-ud --extensions-dir .build/smoke-ext` (a short path: the main-process socket path is limited to 103 characters), `./scripts/code.sh --agents` must be rejected as an unknown option, and `npm run gulp compile-extensions`.
