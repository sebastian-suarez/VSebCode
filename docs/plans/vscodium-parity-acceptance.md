# VSCodium parity scope and acceptance

Both independent implementations receive this document, the same original request and maintainer answers, repository instructions/guides, and the pinned VSCodium source. These are behavioral acceptance criteria; tests must exercise actual behavior and failure paths, not merely match implementation text. The parent runs the same checks and tests on both drafts. No draft may depend on unprovided work from its rival.

## Approved boundaries

- Preserve all removed AI/chat, account, sync, telemetry-sender, tunnel, self-update, server/REH and standalone-web products and their removal manifest. Preserve the local Settings search, theme walkthrough, narrower unavailable-signature-verifier behavior, current Marketplace defaults, source maps, product identifiers and internal macOS launcher decision.
- The new announcements URL is `https://raw.githubusercontent.com/sebastian-suarez/VSebCode/main/announcements-extra.json`; use an empty feed initially unless actual announcement content exists. Policy organization is `Sebastian Suarez`, Windows vendor segment is `SebastianSuarez`, and Linux policy file is `/etc/vsc/policy.json`. Keep generator/runtime paths consistent.
- Linux and Windows implementation is included; their runtime/release validation remains deferred because the current validation host is macOS. Do not remove working macOS signing helpers or claim support was exercised on other hardware.
- The v10 UI reference guides compatibility; this task adds configurable typography and announcements, not the mockup's entire redesign. Existing typography defaults must remain visually equivalent until settings are changed.
- Do not hand-edit generated API/policy outputs or any lockfile. The parent regenerates them through supported commands. Preserve copyright obligations and add the VSCodium MIT notice for imported substantial code in the appropriate notice artifact.
- No commits, pushes, publication, signing, notarization, external messages, or changes to unrelated local tooling state. No permission, signing or hook bypasses. A newly discovered conflict must be reported with concrete options before changing the conflicting behavior.

- Electron stays at 43.7.7 for all architectures, as explicitly chosen by the maintainer. Record a prerequisite matrix for Electron, native modules, ripgrep, compiler, sysroot and package mappings. - Product precedence is packaged defaults, existing development overrides, the selected user-data product.json, then the six gallery environment overrides. Only a plain-object root is accepted; invalid JSON, null, arrays and scalar roots are ignored with a diagnostic. Within valid objects, plain objects merge recursively, arrays replace, and null/scalars replace. Ignore prototype-pollution keys at every depth.
