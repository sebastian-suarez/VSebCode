# VSCodium parity implementation

Implement every missing behavior and the compatible remainder of partial behavior identified in the 15 October audit of VSCodium `be70704abf84fc6c7721f94478dfcccd2dc6163e`. Start both independent attempts from VSebCode `0778ae2564bc0682c3947fb59378f8cf278ab5a3`. The complete scope and shared acceptance criteria are in [vscodium-parity-acceptance.md](vscodium-parity-acceptance.md).

The maintainer explicitly approved command filters, control-feed options/connection behavior, welcome/channel conveniences and post-install telemetry-hostname rewriting, then expanded the request to all missing and compatible partial effects. On follow-up, the maintainer chose to preserve existing removals, signature handling, local Settings search and the theme walkthrough. The approved new values are the VSebCode repository's `main/announcements-extra.json` feed, policy organization `Sebastian Suarez`, Windows vendor segment `SebastianSuarez`, and Linux policy directory `/etc/vsc`.

1. Review this plan before implementation. Resolve any additional genuine conflict with existing work through the maintainer; continue independent work while a decision is pending. Compare UI changes with the v10 design reference without importing an unrelated redesign.
2. Create two isolated linked worktrees at the same starting commit. Supply the same scope, constraints, source patch snapshot and acceptance criteria to both independent attempts; neither sees the other's draft. Do not share mutable dependency/output directories. The parent installs dependencies, generates outputs and runs checks for each attempt. If an explicitly required implementation model is unavailable, report it and ask how to proceed instead of silently substituting.
3. Implement runtime settings and behavior: command filters, control manifest opt-out/connection header, announcements and channel guard, product/gallery overrides, extension release-age gate, reusable banner suppression, generic extension compatibility data and orphan setting cleanup. Preserve defaults and scope where the maintainer retained a prior decision.
4. Port the full surviving UI-font capability, including shared metrics, CSS and layout/virtualization integration; omit deleted AI/session targets. Keep existing defaults and the approved design direction. Verify dynamic changes and reset behavior rather than adding settings alone.
5. Implement dependency, policy, preparation and packaging parity: remove the proprietary build signer, use compatible native packages/prebuilts, make build tree-sitter optional, split prepack/packing tasks, disable private mangling/macOS packaging stats, add safe post-install and built-in-download telemetry-host rewriting, and rebrand policy/DMG outputs. Regenerate locks through npm only and retain required license notices.
6. Port surviving Linux/Windows effects and extra architecture recognition/build support with their acquisition and package dependencies. Preserve the deleted server/CLI products and required macOS signing helper. Keep platform execution limits explicit; Linux/Windows source support does not claim release certification.
7. The parent runs the shared acceptance suite on each complete draft and inspects the resulting diff, dependency graph, removal invariant and packaged macOS behavior. Select one whole passing attempt using the existing routing rule; allow at most one correction attempt each if neither passes. Do not splice rival drafts. Never promote a failing attempt by weakening the acceptance criteria.
8. Integrate the selected whole draft into the main checkout without overwriting unrelated work, then run checks affected by integration. Obtain the required fresh artifact-only and task-aware reviews, validate every finding, and log rejected findings with evidence. Stop after two review/fix rounds. Update the audit follow-up ledger with implemented effects, preserved conflicts, unresolved items and exact validation limits. Do not commit, push, sign, notarize or publish without a separate instruction.

The semver ASAR exception remains an explicit investigation: add it only if a surviving external consumer is demonstrated; do not recreate the removed sandbox merely to justify it. Dormant/obsolete patches, unrelated lockfile churn, old runtime downgrades and removed-product release automation are outside the missing/partial implementation scope.

The plan attack identified seven acceptance gaps: a common executable oracle, architecture prerequisites, source-map integrity after rewriting, override precedence, real shell argument tests, optional-dependency absence, and announcement caching. The acceptance document now fixes these contracts. The maintainer chose to require the current Electron 43.7.7 runtime on every new architecture and explicitly block unavailable builds; an unsupported lane is recorded as blocked, never counted as a successful build. The shared parent-owned fixtures and command manifest are frozen before either draft is judged; any additions apply identically to both drafts.
