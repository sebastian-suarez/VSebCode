## Which assets actually activate, in what order and for which targets?

### Takeaway

The release patch set is staged, not recursive. Preparation applies root JSON removals before ordinary root patches, then Insider, host-OS and user patches. Separate CI packaging jobs apply deeper Linux-client, Linux-REH/architecture and Alpine-REH patches after the prepared source archive is extracted. `.patch.no` assets are dormant; the single `.patch.yet` has an explicit condition. Development helper patches are not part of a normal release build.
